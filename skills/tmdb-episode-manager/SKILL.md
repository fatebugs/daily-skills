# TMDB 分集创建与校正

只处理 TMDB 的分集记录：核对来源、发现漏集、创建新集、顺延编号，以及校正标题、首播日期和时长。剧照上传由独立的分集剧照 skill 处理。

## 确定数据范围

先确认剧集、季、起始和结束范围、当前 TMDB 集数、来源站点和本地目录。用户说“继续新增”时，以 TMDB 当前最后一集和本地目录的实际连续范围为准，不沿用历史会话的最后编号。

建立一份映射表：

| 字段 | 内容 |
| --- | --- |
| 来源总集号 | 来源视频或目录中的原始集数 |
| TMDB 集号 | 当前季内的集数 |
| 标题 | 来源当前标题，去除不属于 TMDB 标题的集数前缀 |
| 首播日期 | 来源页面显示的日期，按站点时区和页面语义记录 |
| 时长 | 来源列表或本地视频读取到的时长 |
| 状态 | 已存在、待校正、待创建、已保存、待复核 |

## 核对来源与漏集

优先使用原作者的单集发布页、投稿列表或用户指定的一手目录；转载目录只能作为辅助。逐项比较编号、标题顺序、日期和时长，不能只看当前 TMDB 的集数是否连续。

- 预期数量使用包含两端的计算：`结束编号 - 起始编号 + 1`。
- 发现缺口时同时列出前后相邻的来源集、当前 TMDB 集和不确定的对应关系；无法确定时保留待确认状态，不把猜测写入 TMDB。
- 来源标题可能有“第 N 集”前缀、特殊标点或文件名限制。去除前缀时保留正文和标点，不按记忆改写标题。
- 来源上传日期不必然等于首次播出日期。遇到补档、重传、同日连更或跨时区情况，记录依据并保持日期的真实顺序。
- 时长优先取来源列表显示值；列表没有时再从本地视频读取。读取不到时长就标记缺失，不用相邻集时长代替。

同一季出现漏集时，先确定插入位置，再计算其后的 TMDB 集号。改号前保存旧编号到映射表，避免把后续条目的标题、日期或时长错位。

## 在 TMDB 中创建和校正

在当前 TMDB 编辑页内分批操作，减少反复打开来源页面和账号风控。先处理一小批并保存，再刷新验证字段确实落库，然后继续下一批。

创建或校正每集时：

1. 定位目标集号，确认当前标题和前后相邻集。
2. 填入来源标题、首播日期和时长；新增集按正确的顺延编号插入。
3. 保存当前批次，等待明确的保存完成状态。
4. 刷新或重新读取列表，抽查刚保存的集数、标题、日期、时长和顺序。
5. 记录已保存范围，再继续下一批。

不要把浏览器表单里显示的暂存值当作已保存。遇到输入框自动格式化、日期被转换、保存后跳回或网络错误时，先重新读取当前条目再重试，避免重复创建。确认单条结果不明时不要连续点击保存。

## 依据本地目录继续创建

当用户要求按本地媒体目录继续新增时：

- 先枚举实际目录并解析集数、标题和文件扩展名；跳过无法识别、重复或范围外目录。
- 用本地视频计算时长时说明测量方式和精度；文件名可能受 Windows 限制，TMDB 标题仍以来源页面为准。
- 将目录集数映射到 TMDB 当前季编号，先检查目标编号是否已经存在，避免重复创建。
- 批量新增后刷新整季列表，检查编号连续、无重复、无意外空集，并确认最后一集与本地目录范围一致。

## 进度与最终报告

长批次每完成一小段就记录断点，至少包含已保存范围、待处理范围、异常集和最后核验时间。页面访问频率受限时优先使用已取得的列表资料，减少重复打开页面。

最终区分：

- 仅完成核对；
- 已保存校正；
- 已创建新集；
- 刷新后已复核；
- 仍有待确认或保存失败的条目。

简要报告实际集数、是否补齐、标题/日期/时长是否更新，以及未确定事项。不把“表单已填写”说成“TMDB 已保存”。
